TCRM-Evolution-Status-Health-Split-V1
=====================================

PURPOSE
-------
Fix the misleading "Evolution offline" badge in the WhatsApp Inbox.

ROOT CAUSE
----------
The inbox currently derives the badge from:
  Boolean(statusQ.data?.success)

getStatus.success is tied to:
  GET /instance/fetchInstances

Therefore any fetchInstances error (401, 404, 5xx, timeout, version mismatch)
is displayed as "Evolution offline" even when Evolution itself is reachable
and TCRM still has chats/counts in its local database.

PATCH BEHAVIOR
--------------
This patch keeps the existing getStatus.success semantics for compatibility,
but adds a separate gateway connectivity classification:

1) online
   - /instance/fetchInstances succeeds.

2) degraded
   - fetchInstances fails, but Evolution still returns an HTTP response
     OR the fallback /healthz check responds successfully/reachably.
   - Inbox displays:
       EN: Evolution online · status unavailable
       AR: Evolution متاح · حالة الحسابات غير متاحة
   - Admin can see the HTTP code / sanitized error detail.

3) offline
   - neither fetchInstances nor /healthz returns an HTTP response
     (transport/DNS/TLS/connection/timeout type failure).

PERFORMANCE
-----------
/healthz is only requested when /instance/fetchInstances fails.
Healthy installations do NOT get an extra Evolution request every refresh.

----------------------

------

- NO account assignment changes.
- NO webhook signature changes.
- NO TOS/THRS/TFS changes.
